# Card

관련된 정보를 하나의 surface 위에 명시적으로 조합하는 layout 컴포넌트입니다.

<h2 id="usage">사용 기준과 기본 예제</h2>

### 사용할 때

- 제목, 설명, 본문, action처럼 서로 연관된 정보를 독립된 묶음으로 보여 줄 때 사용합니다.
- 목록에서 반복되는 정보 block의 위계와 경계를 일관되게 유지할 때 사용합니다.

### 사용하지 않을 때

- 클릭 가능한 Card, 미디어 비율, product 전용 grid 같은 layout을 Card prop으로 추상화하지 않습니다.
- 페이지의 주 제목과 대표 action에는 `PageHeader`를 사용합니다.

<h2 id="composition">구성 방식</h2>

`Header`, `Title`, `Description`, `Content`, `Footer`는 필요한 부분만 명시적으로 조합합니다. `Card.Title`은 기본적으로 `div`를 렌더링하므로 heading 위계가 필요하면 `asChild`와 실제 heading을 함께 사용합니다.

<Canvas of={CardStories.WithoutFooter} sourceState="shown" />

<h2 id="props">주요 API와 native props</h2>

`Root`, `Header`, `Content`, `Footer`는 native `div`, `Description`은 `p`를 렌더링합니다. 모든 하위 component는 `className`, `data-*`, `aria-*`, ref를 실제 DOM 요소에 전달합니다.

<Controls of={CardStories.Playground} />

<h2 id="accessibility">접근성</h2>

- Card 자체는 layout `div`이며 interactive semantics를 추가하지 않습니다. 이동에는 내부 link, 실행에는 내부 button을 소비자가 선택합니다.
- 제목이 콘텐츠의 구조를 나타내면 `Card.Title asChild`로 적절한 `h2`~`h6`를 전달합니다.
- 상태를 Badge 색상으로 표시할 때는 색상 외에도 상태 텍스트를 함께 제공합니다.

<h2 id="tokens">토큰 커스터마이징</h2>

Card의 surface, border, radius, shadow는 `--dds-color-bg-surface`, `--dds-color-border-default`, `--dds-radius-*`, `--dds-shadow-*` semantic token을 따릅니다.

```css
[data-dds-brand="project"] {
  --dds-color-border-default: var(--dds-color-brand-200);
  --dds-radius-md: var(--dds-radius-lg);
}
```
